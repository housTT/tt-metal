Notes

W1 fix, proven. The stall was a shape-keyed prefill page-table buffer allocating under the resident decode trace when concurrent requests batched into a (num_reqs>1, serve_w) prefill (warmup only covered row-count 1). Warmup now pre-allocates every (1..max_num_seqs, serve_w) shape. Across this whole sweep — every C=8 run included — a diagnostic counted 0 serving-time prefill-pt allocations. The server needed no client warmup pass to get clean numbers.
C=8 mean-ITL spikes are prefill saturation, not W1. At 16k/32k, launching 8 requests at once saturates prefill; a request's decode intervals stretch while the engine prefills the others (Mean ITL 127/501 ms). But P99 ITL stays ~43–46 ms — decode itself never stalls — and the 0-alloc proof rules out a recompile stall. This is a benchmark all-at-once-arrival artifact; ramped arrival avoids it. 128k @ C=8 is omitted (the ~164k-token KV pool can't hold 8 long contexts).
Metric conventions. Cold (APC off); t/s/u = 1000/mean_TPOT; aggregate = output throughput; E2EL/ITL measured. Decode SDPA = accurate k64. "Before" = the pre-fix cold baseline (STATUS: 25.3/23.7/22.2/13.5 t/s/u; TTFT 0.7/12.9/29.8/299 s).
