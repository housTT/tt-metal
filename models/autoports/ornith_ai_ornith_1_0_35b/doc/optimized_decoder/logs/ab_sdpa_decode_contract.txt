# Three paged-flash-decode candidates that are faster in isolation. Two are WRONG in the layer; the third
# is correct there and buys nothing, which is a different rejection and is recorded as one.
#
# `probe_decode_micro.py --section sdpa` times the op standalone against its own default output as
# the reference, on one contiguous page table. That reference cannot see either failure below,
# because both arms compute the same wrong thing in isolation. The layer's HF-golden PCC does see
# them. Both are therefore rejected on correctness, with the numbers the delivered suite printed.
#
# Reproduce either by editing OptimizedDecoder.__init__ / _attention_decode as noted and running:
#   python -m pytest models/autoports/ornith_ai_ornith_1_0_35b/tests/test_optimized_decoder.py \
#       -p no:randomly -q -k "decode_pcc or traced_decode or ragged or above_head_split"
# Bar: PCC > 0.995. Shipped config: SDPAProgramConfig((8,8), q_chunk 32, k_chunk = page_block_size
# = 64, exp_approx_mode=False), and NO compute_kernel_config.
#
# --- candidate A: k_chunk_size = 128 (probe: 55.9-57.2 us vs 61.2-63.7 at 64, i.e. ~10% faster) ---
# k_chunk_size 128 > page_block_size 64.
FAIL test_batched_decode_ragged_positions   user 3 at position 192   PCC 0.8334597477790499
FAIL test_decode_pcc                        decode step 0           PCC 0.9051200320078158
FAIL test_traced_decode_pcc                 replay step 0           PCC 0.8911847819527839
FAIL test_decode_pcc (other layer kind)     decode step 0           PCC 0.022923705334755486
# 5 of 16 selected cases failed; the standalone probe reports pcc_vs_default=0.999398 for the same
# config, i.e. the isolated op agrees with itself. Rejected: k_chunk_size is pinned to
# page_block_size in code, not to the literal 64.
#
# --- candidate B: pass the prefill SDPA compute-kernel config (HiFi2, fp32_dest_acc_en=True) ---
# to paged_scaled_dot_product_attention_decode, which the fused decoder left unset.
FAIL test_batched_decode_ragged_positions   user 0 at position 70    PCC 0.9244205427863718

# Rejected: the decode call deliberately passes no compute_kernel_config, and the call site says so.
# With both candidates reverted the same 16 cases pass.

# --- candidate C: q_chunk_size = 0, k_chunk_size = 0 (probe: 55.6-56.8 us vs 62.0 at the shipped
#     32/page_block, i.e. ~9% faster in isolation, measured on all four grids) ---------------------
# Raised by review round 7, which observed the candidate measured everywhere and dispositioned nowhere,
# and inferred from its `pcc_vs_default` fingerprint that it would collapse like candidate A. It does
# NOT. Measured rather than inferred, on the shipped code with only this config changed:
#
#   PASS  the whole delivered suite, 109 passed / 0 failed
#   PASS  every case of the selection candidates A and B fail: 16 passed / 0 failed, worst PCC 0.999865
#         (decode_pcc, traced_decode, batched ragged positions, above_head_split, batch-32 prefill+decode)
#
# So the correctness argument that rejects A and B does not apply here. What rejects it is that the win
# does not exist at the layer:
#
#   shipped  (8,8) q32 k=page_block   full_attention traced decode  0.849 ms   (ab_fused_vs_optimized.txt)
#   q0 k0                             full_attention traced decode  0.848 ms   (same harness, same weights)
#
# One microsecond, inside the run-to-run spread, because SdpaDecode is ~2% of the decode window and a 5 us
# op-level difference has nowhere to go. Set against that: k_chunk_size=0 hands the chunk choice to the op,
# and candidate A is the proof that a chunk larger than page_block_size is silently wrong at this model's
# paged geometry. Keeping the chunk pinned to page_block_size in code costs nothing measurable and keeps the
# invariant checkable from outside the op. Rejected on "no layer-level gain", not on correctness.
