### State-dict key mapping decision

`Qwen36ModelArgs` already accepts the `model.language_model.` prefix. `remap_qwen36_state_dict` (`/home/hous/dev/clef/tt-metal/models/demos/blackhole/qwen36/tt/weight_mapping.py`, lines 58 to 63) strips `model.language_model.` or `model.`, maps `embed_tokens.weight` to `tok_embeddings.weight`, `norm.weight` to `norm.weight`, `lm_head.weight` to `output.weight`, renames `linear_attn.in_proj_qkv.weight` to `linear_attn.qkv_proj.weight`, and splits `linear_attn.conv1d.weight` at rows 2048 and 4096 into `q_conv`, `k_conv`, `v_conv`. The split constants are the 9B values (16 key heads times 128), and Clef has the same 16 key heads times 128, so the split is correct here too: shapes `[2048, 1, 4]`, `[2048, 1, 4]`, `[6144, 1, 4]` (checked in `test_load_state_dict_four_layers`). The TP GDN loader (`/home/hous/dev/clef/tt-metal/models/demos/blackhole/qwen36/tt/gdn/tp.py`, lines 111 to 125) accepts either layout and reassembles the fused conv.

The subclass therefore stays thin. `ClefModelArgs.load_state_dict()` differs from the parent in how the raw tensors are read, not in the mapping:

- The parent instantiates `Qwen3_5ForCausalLM.from_pretrained(CKPT_DIR)`, which materializes the whole text model (including `lm_head.weight`, 2.5 GB) before remapping.
- `ClefModelArgs` reads only the `model.language_model.*` tensors of the active layers (`n_layers` or `layer_indices`) plus `embed_tokens` and `norm` straight from the shards with `safe_open`, then calls the same `remap_qwen36_state_dict`. It never reads `model.visual.*` or `lm_head.weight`, so the returned dict has no `output.weight`.

`tests/test_loader_cpu.py::test_mapped_keys_match_parent_expectation` derives the expected key set programmatically: it builds `Qwen3_5ForCausalLM` from Clef's `Qwen3_5TextConfig` on the meta device with 4 layers, runs the parent's `remap_qwen36_state_dict` on its `state_dict()` keys, and asserts the result for layers 0 (GDN) and 3 (full attention) equals `ClefModelArgs.mapped_keys({0})` and `mapped_keys({3})` (plus `tok_embeddings.weight` and `norm.weight`). Both sets have 18 and 13 keys.

### Encoding and the split rule

`encode(tokenizer, record, processor=None, max_length=16384, max_state_tokens=None)` calls the release `encode_record` unchanged. The release module is loaded from `<snapshot>/joint_schema_model.py` with `importlib` under the module name `clef_release_joint_schema_model`.

The release sequence is `prefix_ids + media_ids + state_ids + schema_ids + suffix_ids` (`joint_schema_model.py`, `encode_record`). `split_for_cache(encoded, tokenizer, record)` recomputes `schema_ids` with the same tokenizer calls and the same loop as the release function (`schema_ids_and_question_starts`), recomputes `suffix_ids`, and sets `split = len(input_ids) - len(schema_ids) - len(suffix_ids)`. It then checks three things and raises `ValueError` on any mismatch: `input_ids[split:] == schema_ids + suffix_ids`; `input_ids[:len(prefix_ids)] == prefix_ids`; every `question_span[0]` equals `split` plus the recomputed in-schema question start. It returns `(input_ids[:split], input_ids[split:], encoded.questions)`. The spans in the returned questions are unchanged, so they are relative to the full sequence. The first piece is the prefix-cache key material (`cache_key(ids)` = sha1 over the little-endian int32 bytes); the second piece is the continuation.

Parity evidence (`tests/test_encode_parity.py`): 50 records (the 16 reference records from `/home/hous/dev/clef/reports/reference/records_text.jsonl` plus 34 from `/home/hous/dev/kev/kev/evals/documents-v1/development.jsonl` with `_meta`, `label` and `src` stripped) encode field by field equal to the release `encode_record`, and `split_for_cache` concatenates back to `input_ids` with the spans inside the second piece. Two synthetic records cover `noul`, `choice` and `score`, a dict state, `max_state_tokens` truncation and `max_length` truncation; the split equals `len(prefix_ids) + len(state_ids)` in each case.

### Head contract

`JointSchemaHead.forward(hidden_states, input_ids, attention_mask, records, output_embedding_weight)` applies its own `hidden_norm` (`torch.nn.LayerNorm(5120)`) first, then runs the per-record math. Its `hidden_states` argument in the release (`ClefModel.forward`) is `outputs.last_hidden_state` of `Qwen3_5TextModel`, which is the output of the text model's final RMSNorm (`model.language_model.norm`). So the tensor the engine must hand to the head is: the backbone's final-RMSNorm output for every position, `[T, 5120]`, cast to fp32. Not the pre-norm residual, and not logits.

`probs_for_record(head, hidden_fp32, input_ids, encoded_record, lm_head_rows_fn)` wraps the vendored forward for one record: `hidden_fp32 [T, 5120]`, `input_ids [T]`, an all-ones attention mask, `[encoded_record]`, and a `RowGather` object whose `__getitem__(token_ids)` returns `lm_head_rows_fn(token_ids).float()`. The forward indexes `output_embedding_weight[token_ids]` once per option span, so only the rows of the option tokens are read. It returns `{question_id: {option_id: probability}}` with `softmax(-1)` per question, the same reduction `systemone()` uses. `logits_for_record` returns the raw per-question logits.

### Mesh and model path

`tp2_mesh()` is stage 0 path A: `ttnn.set_fabric_config(FABRIC_1D)`, `open_mesh_device(MeshShape(1,4), l1_small_size=24576, num_command_queues=2, trace_region_size=0)`, `create_submesh(MeshShape(1,2), MeshCoordinate(0,0))`, `enable_program_cache()` on the submesh; teardown synchronizes, closes `parent.get_submeshes()`, then the parent, then sets `FabricConfig.DISABLED`. Collectives are stock `qwen36` (2 links, `Topology.Ring`), as stage 0 validated.

`ClefEngine(mesh, args_cls=ClefModelArgs, max_state_len=16384, chunk_size=1024, snapshot_slots=4, n_layers=None, max_tail_len=4096, cache_reload=None, kv_reserve_bytes=2 GiB, prefill_only_mlp=True)`:

- `max_len = max_state_len + max_tail_len = 20480` is the `Qwen36ModelArgs.max_seq_len` (RoPE table size) and the KV blocks per slot (`20480 / 64 = 320`). `chunk_size` must be 1024 (stage 0 finding 2: the 2048 bucket overflows L1 at TP=2); the masked buckets are 128, 256, 512, 1024.
- Forward: the engine calls `Qwen36Model._forward_prefill_chunk_masked_tp(token_buf, valid_len, chunk_start, page_table, bucket)` directly, never the logits wrappers. At a sequence start it calls `_reset_gdn_state_for_new_sequence()` (the TP in-place zero of `rec_state`, `conv_states`, `conv_carry`) and `_build_request_rope(ids, None)` (text: clears the M-RoPE table), which is what `prefill_masked_bucket` does before its forward.
- Readout: `self.model.norm(hidden, mode=Mode.PREFILL)` (the `DistributedNorm`: distributed RMSNorm on the fractured `[1,1,bucket,2560]` hidden, then an all-gather to the replicated `[1,1,bucket,5120]`), `ttnn.to_torch(..., mesh_composer=ConcatMeshToTensor(mesh, dim=0))[0]`, trimmed to `valid_len`, cast to fp32. This is the tensor the head consumes (see "Head contract" above).
- `prefill_hidden(token_ids, slot=0) -> [T, 5120] fp32`: 1024-token chunks at `chunk_start = 0, 1024, ...` with the last chunk in the smallest bucket that fits; the GDN state carries across chunks in place (`_stable_state=True`, set by `_allocate_kv_caches_tp`) and the paged KV of the slot carries through the page table. The call invalidates any cached state in that slot (its KV pages are overwritten).
- `prefill_state(state_ids, slot, key=None) -> StateHandle(S, S0, suffix_ids, slot, key)`: `S0 = (S // 128) * 128` (the GDN chunk kernel and the flexible chunked SDPA need a 128-aligned `chunk_start`), runs `[0, S0)` as above, keeps the normalized hidden of those `S0` rows on host (`engine.prefix_hidden[slot]`, fp32, 320 MiB at `S0 = 16384`), and snapshots the GDN state into per-slot device buffers with `ttnn.copy`: `rec_state` (fp32 `[1, 24, 128, 128]` per device per GDN layer) and `conv_carry` (bf16 `[1, 3, 5120]`). `conv_states` is the decode window and is not needed by prefill. The single-device `_save_deltanet_states` is not used. Snapshot cost per slot: 48 layers x (1.5 MiB + 0.3 MiB) = 87 MiB per device.
- `schema_hidden(handle, schema_ids) -> [len(state_remainder) + len(schema), 5120]`: restores the slot's GDN snapshot into the live state with `ttnn.copy`, clears the RoPE table, and runs `suffix_ids + schema_ids` as one or more 1024 chunks at `chunk_start = S0, S0 + 1024, ...` through the slot's page table (the KV pages of `[0, S0)` are intact; the tail pages are rewritten on each call). Repeated calls are bit-equal (asserted by the test).
- `probs_for_request(record, mode="full"|"cached", slot=0)`: `encode.encode` (release `encode_record`), then `prefill_hidden` (full) or `encode.split_for_cache` + `cached_hidden` (prefix cache keyed on `cache_key(state_part)`, hit when the slot already holds that key; the hidden handed to the head is `prefix_hidden[slot]` concatenated with the tail rows), then `head.probs_for_record` (fp32 head, `lm_head` rows from the safetensors) and `systemone_answer` per question. Returns `model`, `answers`, `usage`, `probs`, `input_tokens`, `seconds`, `timing` (encode, device, head), `mode`, `cache_hit`.
- Slots: `_fit_slots` computes the per-slot bytes (KV: 2 x 16 attention layers x 320 blocks x 2 local KV heads x 64 x 256 x 2 B = 0.625 GiB; GDN snapshot 87 MiB) against the DRAM free after the weights (`ttnn.get_memory_view(mesh, BufferType.DRAM)`, `total_bytes_free_per_bank x num_banks`), keeps `kv_reserve_bytes` for activations, and allocates `min(requested, fit)` slots in one `allocate_kv_caches` call (replicated per device, `[slots x 320, 2, 64, 256]` bf16). Page table of slot `s` = blocks `[s x 320, (s+1) x 320)`.

### `output.weight` decision

`Qwen36Model.__init__` reads `state_dict["output.weight"]` unconditionally (`/home/hous/dev/clef/tt-metal/models/demos/blackhole/qwen36/tt/model.py` line 124) and only uploads it as `self.lm_head_weight`; `_lm_head` is the only consumer and the engine never calls a logits wrapper. The engine passes a stub `torch.zeros(num_devices x 32, 5120)` (bf16): `vocab_rows % num_devices == 0` keeps the vocab-sharded branch, each device receives a `[5120, 32]` bfp8 tile column (0.3 MB), and `_lm_head` is replaced by a method that raises. A shape-correct stub would cost 0.67 GiB of DRAM per device and a 2.5 GB host tensor for nothing. `ClefModelArgs.load_state_dict` still never reads the real `lm_head.weight`; the head's lexical rows come from `LmHeadRows` on host as before.

### Prefill-only MLP weights

The TP `load_mlp_weights` (`/home/hous/dev/clef/tt-metal/models/demos/blackhole/qwen36/tt/mlp.py` lines 50 to 160) uploads `w1`, `w3` (decode) and the packed `w_gate_up` (prefill, fused SwiGLU all-gather matmul). `Qwen36MLP._forward_tp` uses only `w_gate_up` for any input taller than one tile, so `w1` and `w3` are dead weight in a prefill-only engine: 6 GiB per device at bfp8 (12 GiB at bf16). `prefill_only_mlp_weights()` replaces `mlp.load_mlp_weights` during the model build with a loader that builds `w_gate_up` (`_build_gate_up`) and `w2` (`tpc.shard_w`, dim 0, interleaved, `MLP_DOWN_DTYPE`) exactly as upstream does and returns `MLPWeights(w1=None, w3=None, ...)`. It only applies when the upstream conditions for the fused path hold (`num_devices > 1`, `mlp_1d_decode`, `mlp_gateup_agmm_enabled`); otherwise it defers to the original loader. No `qwen36` file is modified.

### Precision (stage 1 values, stage 4 owns the sweep)

`tt/precision_defaults.py`: `QWEN36_MLP_GATE_UP_DTYPE=bfp8`, `QWEN36_MLP_DOWN_DTYPE=bf16`, `QWEN36_PROJ_DTYPE=bfp8`, `QWEN36_MATMUL_FIDELITY=HiFi2`, `QWEN36_GDN_GATE_FP32=1`. Tensor cache tag (unused for files, see below, but part of the `weight_cache_path` name): `gu-bfp8_dn-bf16_pj-bfp8`. The engine logs the dtypes and fidelities actually present on the device at every start (`ClefEngine device dtypes and fidelities: ...`): with these knobs, MLP gate/up packed `BFLOAT8_B`, MLP down `BFLOAT16`, GDN `qkvzab` and `out_colpar` `BFLOAT8_B`, attention qkv and wo `BFLOAT8_B`, embedding `BFLOAT16`, GDN recurrent state `FLOAT32`, GDN `dt_bias` `FLOAT32` (gate fp32 on), fidelity `HiFi2` for MLP, GDN and attention.

- bf16 gate/up was tried first and is not runnable at TP=2: the fused SwiGLU all-gather matmul (`tp_common.py` line 444, fixed `MinimalMatmulConfig`) fails with `Statically allocated circular buffers in program 168 clash with L1 buffers on core range [0-0 - 7-8]` at bucket 512 (`/home/hous/dev/clef/logs/stage1_engine_l4_t300_debug.log`). The config is sized for the bfp4/bfp8 weights upstream validated; `tp_common.py` is outside the allowed change set. bfp8 is therefore the best available gate/up precision here (the `qwen36` default is bfp4).
- bf16 down projection runs at every bucket (plain `ttnn.linear` with the 2D prefill program config).
- `QWEN36_PROJ_DTYPE` has no effect on the TP path upstream: the TP attention and GDN loaders pass `dtype=ttnn.bfloat8_b` to `tpc.shard_w` directly (`attention/tp.py` lines 65 to 110, `gdn/tp.py` lines 150 to 205). The engine makes it effective through `tp_proj_dtype()` (a `tp_common.shard_w` override active during the model build when the knob is not bfp8). bf16 projections were measured (work log 09:31 ET): identical PCC to bfp8 at every layer, twice the load time, 20.4 GiB of weights per device; stage 1 keeps bfp8.
- `QWEN36_GDN_GATE_FP32=1` (new, see "GDN decay gate precision" below) is the one knob that changes the 64-layer result.
- `QWEN36_MATMUL_FIDELITY` is read by `mlp.py` (all MLP compute configs) and by the single-device attention and GDN modules; the TP attention and GDN modules carry their own compute configs.

### AutoDebug conclusion (cache reload spin)

Report: `/home/hous/dev/clef/tt-metal/AUTODEBUG.md` (inspection only, no device run; launcher log `/home/hous/dev/clef/logs/stage1_autodebug_cache_reload.log`). Summary of its findings, verified against the checkout where stated:

- The flatbuffer load only `mmap`s the file (`ttnn/core/tensor/serialization.cpp` lines 79 to 130), which is why the host-only `load_tensor` returns instantly. Both failing patterns converge on `MeshCommandQueue::enqueue_write_tensor` (`tt_metal/impl/tensor/tensor_apis.cpp` lines 155 to 215).
- That write has a size gate: above 32 MiB of local shard bytes (`k_pin_write_threshold_bytes`, `tensor_apis.cpp` lines 39 to 47) it pins the host pages and lets the device prefetcher read them over PCIe (`CQ_PREFETCH_CMD_RELAY_LINEAR`); below it, it copies through the command queue. The 2.6 MB probes never pin; the 45 MB and 2.5 GB tensors do. The fresh 45 MB `as_tensor` write from a torch tensor also pins and works, so the difference is the host memory handed in: a read-only, file-backed `MAP_PRIVATE` mapping with 64-byte-aligned shards (no-prefix dispatch branch) versus anonymous heap memory. The report ranks two candidate mechanisms (read-only file-backed pins, and the no-prefix pinned dispatch branch, which has no CI coverage on hardware with read-only pinning) and marks both unproven; it notes the operation timeout defaults to 0 so a device that never completes is waited for forever, which matches the 100% CPU poll on the host.
- Workaround without a tt-metal change: `TT_METAL_PINNED_MEMORY_CACHE_LIMIT_BYTES=0` in the loading process (`tt_metal/llrt/rtoptions.cpp` lines 656 to 685; a limit of 0 makes `try_pin` return null and the write falls back to the copy path, the path every CI runner takes). Cost: every host-to-device write above 32 MiB copies through the command queue instead of DMA. Second option: `load_tensor` then `to_torch` then `from_torch` with the mesh mapper (a heap source), at the cost of a decode and re-encode per load.
- Confirmed on the device (09:59 ET, `/home/hous/dev/clef/logs/stage1_cache_reload_probe_parent_nopin.log`): with `TT_METAL_PINNED_MEMORY_CACHE_LIMIT_BYTES=0` the same 45 MB sharded tensor reloads in 0.00 s through the stock `as_tensor` path and through `load_tensor` + `to_device`. The engine now sets that variable in its device setup (`tt/engine.py` sets `os.environ.setdefault("TT_METAL_PINNED_MEMORY_CACHE_LIMIT_BYTES", "0")` before `import ttnn`, so every process that imports the engine, including the tests and scripts, runs with pinned host memory off). The stage 1 default stays `cache_reload="off"` (no cache files; validated at 64 layers); `cache_reload="stock"` is the stage 3 candidate for fast server starts after one cache-writing run (about 20 GB of files for 64 layers at the stage 1 dtypes). Cost of the variable: host-to-device writes above 32 MiB copy through the command queue instead of DMA (the one-time weight upload at start).

### Stage 1 verdict as the implementer sees it

The engine is functionally complete for text: the TP=2 forward, the full-sequence normalized read-out, the per-slot prefix cache (KV page tables plus GDN state snapshots) and the host head reproduce the author's CPU bf16 probabilities on all 16 reference records within max dp 0.0722 with no argmax flip, on 8 long records of up to 16,384 tokens within max dp 0.0557 with no flip, and on 100 BANKING77 rows within max dp 0.1102 with no flip at margin and an identical macro-F1 (0.9113); the cached path is bit-identical to the full-row path on all 124 records and the record-level cache hit reproduces the first cached run exactly, so the parity gate of the plan passes at every length the product serves. The original hidden-state gate is not met at long inputs (worst sampled rows 0.76 at T=1500, 0.98 at T=8192 against the 0.99 bar); under the amended gate of 2026 Oct 05, gate (a) is met at T=300 and T=8192 (`test_layer_floor_gate`), gate (b) is met at T=300 and gate (c) reports the three long lengths next to the HF fp32 control, which shows that HF bf16 itself fails a whole-row 0.99 bar against fp32. The cause of the long-input drift is characterized rather than open: the drift accumulates in the 48 Gated DeltaNet layers, where the bf16 decay gate was the dominant term (fixed under the `QWEN36_GDN_GATE_FP32` flag, which lifted the isolated layer 30 from 0.953 to 0.9997 and the records parity from one flip at max dp 0.285 to none at 0.072) and the remainder is the fused chunk kernel's internal precision on the small-decay heads plus the bf16 conv and bfp8 projections, each measured in isolation against the HF module and against a torch fp32 core on identical inputs, with the GDN layers in the same band as the attention layers (1.2x to 6x the HF bf16 floor on the eight layers where the floor was measured). Closing the original hidden gate at long T needs either a higher-precision path inside `chunk_gated_delta_rule` (a kernel hand-off) or fp32 q/k/v and beta into it (a `gdn/tp.py` change beyond this stage), and I recommend stage 4 measure those on the 200-record set against the parity metrics the product actually uses, where the current configuration already has margin. The checkpoint covers stages 1 and 2 together (see the checkpoint note under "Memory and timing"): the engine carries the vision path, and `CLEF_VISION=0` reproduces the stage 1 text-only engine.
