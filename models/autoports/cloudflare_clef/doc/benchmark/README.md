Footnotes.

- New / repeated state: the first column of each pair is a request whose state the server has not seen (prefix-cache miss: the state prefix is prefilled, then the schema tail runs), the second a request whose state is in the prefix cache (hit: the KV pages and the GDN state of the slot are restored, then the schema tail runs). The worker holds 4 states (`CLEF_PREFIX_CACHE=4`, 4 KV slots of 20,480 tokens: 16,384 of state plus 4,096 of schema). A state under 128 tokens has no cached prefix (`tt/engine.py`: `S0 = (S // 128) * 128 = 0`, the schema tail carries the whole state), so new and cached are equal by construction in the short-state column; the kev ticket state is 122 tokens with the system prompt.
- Model time per request is the server's `latency_ms`: the wall time of the model section of the request on its worker thread (state prefill or cache restore, schema continuation, joint head on the host in fp32). It excludes queue wait and HTTP. Clef decides every question of a request jointly in one pass, so there is no per-question fan-out and one request runs on one TP group.
- Precision (stage 1 values; stage 4 owns the sweep): `QWEN36_MLP_GATE_UP_DTYPE=bfp8`, `QWEN36_MLP_DOWN_DTYPE=bf16`, `QWEN36_PROJ_DTYPE=bfp8` (GDN and attention projections), `QWEN36_MATMUL_FIDELITY=HiFi2`, `QWEN36_GDN_GATE_FP32=1`; bf16 embeddings, bf16 KV cache, fp32 GDN recurrent state, the vision tower in bf16 with fp32 accumulation (stage 2 amendment), host head fp32. No tensor cache files (weights convert from the safetensors at every start, 86 to 110 s).
- Prefill is eager (`CLEF_TRACED=0`): masked buckets of 128, 256, 512 and 1,024 tokens, chunk 1,024, the FIR GDN causal conv kernel on every bucket. The prefix planner (`ClefEngine.plan_prefix`, `doc/optimized/README.md`, "Prefix planner") picks the cached prefix length among the 128-aligned values so that a miss takes the fewest chunk passes without making the hit slower: the 370-token state (406 state tokens with the system prompt, 558-token tail) runs as one 1,024-token pass instead of a 512-token chunk plus a 1,024 pass, the 2,200-token state as 1,024 + 1,024 + a 1,024-bucket tail instead of 1,024 + 1,024 + 128 + tail. The matmul program-config policy of Kev is not applied (`doc/optimized/README.md`, "Perf breakdown"). Why eager and not traced: `doc/optimized/README.md`, "Why eager is the default" (tracing gains 0 to 3 percent at this depth in one process, median of 5, and compiles vision programs after capture for image grids outside its warm list or for more than one image per request).
