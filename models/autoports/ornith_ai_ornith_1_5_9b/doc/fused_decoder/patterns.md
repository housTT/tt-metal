## Functional graph

All weights and constants are setup-time device tensors. Activations and weights
are BF16; recurrent state and gates are FP32. Interleaved DRAM is the external
contract. Table describes one block; public prefill adds chunk slicing, tail
padding/masking, continuation alignment and output concatenation.

| Subgraph | Functional operations and movement |
| --- | --- |
| Entry | RMSNorm(x, zero-centered weight folded at setup) |
| Full projection | Q/gate linear; untilize→reshape→tilize; two slices; gate untilize→reshape→tilize; Q RMSNorm→transpose. Separate K linear→untilize→reshape→tilize→RMSNorm→transpose; V linear→untilize→reshape→tilize→transpose |
| Full RoPE | table slice+tilize (prefill) or embedding to tile (decode); per Q/K: rotary slice, two half slices, neg, concat, two multiplies, add, passthrough slice, concat |

## Evidence and selection status

This ledger covers the known applicable [graph-fusing skill](../../../../../.agents/skills/graph-fusing/SKILL.md) patterns for the **fused decoder stage only**. It records device experiments performed by the coordinator; the documentation author did not access hardware. There was no datatype sweep, matmul-geometry sweep, general performance-tuning stage, full-model work or serving work. Program/layout adaptations were limited to making an existing fused operator express the same graph, with matched controls where program selection changed.

The inventory uses the functional [linear prefill](../functional_decoder/tracy/linear_attention/prefill_ops.csv), [linear decode](../functional_decoder/tracy/linear_attention/decode_ops.csv), [full prefill](../functional_decoder/tracy/full_attention/prefill_ops.csv) and [full decode](../functional_decoder/tracy/full_attention/decode_ops.csv) profiler tables, the graph above, the [attention diagnosis](AUTODEBUG_attention.md), [linear diagnosis](AUTODEBUG_linear.md) and [linear AutoFix report](AUTOFIX_linear.md). Source contracts and tests were inspected before adaptations. Pinned35B wiring was adapted to this checkpoint; none of its performance claims is used as9B evidence.

Unless explicitly stated otherwise, paired numbers below are **candidate wall medians in milliseconds** at B1, prefill2048 and decode position2048, on one Blackhole chip of a P300c board. Each run compares the original functional graph with the candidate using real checkpoint weights; five windows follow two warm windows and each decode window contains32 trace replays. These numbers are not profiler kernel sums and are not interchangeable with the separate128-token inherited perf test. [The measurement table](candidate_measurements.md) contains earlier paired baselines/PCC values; newer exact results are linked directly below. Every log has a same-stem `.provenance.json` recording argv, environment, source hashes and exit status; later runs also preserve a `.sources.json.gz` source snapshot. For example, [combined provenance](logs/conv_final_combination_v1.provenance.json) and its [source snapshot](logs/conv_final_combination_v1.sources.json.gz) identify the tested combination even while production code is being integrated.

“Selected” means included in the integrated runtime, currently SHA256 `18d59502e7e168e584e58762396b9cc61eae6de304045542d15bbcc070f9b11d`, not stage closure. Its refreshed85 short,9 native/long and23 Watcher tests plus four measured HF profiles pass. The earlier84/9-test runs and four initial profiles belong to the previous `3cf319…` source identified below. Earlier candidate measurements remain historical evidence. “Rejected” identifies a measured accuracy/performance result after a supported retry, or a source contract that cannot express this graph. Successful B1 tests never override failed per-user HF tests at B32.

## Final cast and short-prefill handoff resolution

[The isolated cast candidates](../../tests/decode_cast_candidates.py) retain BF16 input/weight policy and FP32 recurrence. Query scaling by the exact power-of-two1/128 emits FP32 directly; value-minus-state-read accepts BF16 V and FP32 read with FP32 output. The key unary chain multiplies by181/2048, rounds the product FP32→BF16 with RNE, then emits FP32. This coefficient is the BF16 representation of1/sqrt128 used by [BinaryNG scalar packing](../../../../../ttnn/cpp/ttnn/operations/eltwise/binary_ng/device/binary_ng_utils.cpp); [unary scalar codegen](../../../../../ttnn/cpp/ttnn/operations/eltwise/unary/common/unary_op_utils.cpp) instead embeds the FP32 immediate, so passing the unrounded Python constant would change the graph. [Blackhole typecast](../../../../../tt_metal/hw/ckernels/blackhole/metal/llk_api/llk_sfpu/ckernel_sfpu_typecast.h) supplies the explicit BF16 rounding. The all-cast pair gives minimum output PCC0.99989795 and traced decode1.461613 ms versus the pre-cast coherent candidate1.492912 ms. This is an op merge preserving rounding, not a precision sweep.

[NormL1InputGDN](../../tests/final_fusion_candidates.py) keeps normalized rank4 Q/K in L1 only when `batch * physical_seq <= 512`; larger allocations remain in DRAM. The [existing chunk reader](../../../../../ttnn/cpp/ttnn/operations/transformer/chunk_gated_delta_rule/device/kernels/dataflow/reader_chunk_gated_delta_rule.cpp) uses TensorAccessor for Q/K, enabling this direct input. The selected rewrite removes the short-chunk copy while bounding L1 use across batches.
