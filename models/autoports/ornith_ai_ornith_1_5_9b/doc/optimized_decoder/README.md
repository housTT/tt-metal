# Ornith-1.5-9B optimized decoder

The optimized decoder preserves the native context and batch contract, passes
real-weight correctness, stress and separate Watcher checks, and improves warmed
prefill and traced decode on the current hardware. Independent review is
recorded in [STAGE_REVIEW.md](STAGE_REVIEW.md).

The stage starts at fused checkpoint `bc8f514f30` and changes only
`tt/optimized_decoder.py`, its tests, and stage documentation. The target is one
Blackhole chip on physical P300c boards (`p150` names the one-chip mesh). The
checkpoint is pinned to `489cb97981b8654bcfcf30ce1f94ed1b62e07b53`.

`record_run.py NAME COMMAND...` preserves each run without overwriting an existing
name. `run_candidates.py PLAN.json` runs a finite plan serially. Plans capture
experimental intent; the per-run provenance captures the resolved environment.
`run_profiles.py LABEL [--baseline]` captures one layer of each kind with separate
prefill and traced-decode windows. Hardware-facing jobs are always serialized;
Watcher and profiling run separately.

## Measurement contract

Paired comparisons use the same real recorded 2048-token prompt and position2048
single-token decode for fused and optimized implementations. Prefill reports the
median of five warmed runs; traced decode reports the median of five windows of
32 replays. State restoration, input transfer, and HF checks occur outside timing.
Linear repeated decode consumes its recurrent state; full attention replays the
same position and therefore overwrites the same cache row. Separate contract tests
exercise changing positions, page tables, ragged batches, and continuation.

The HF output acceptance bar remains PCC0.995. Cache/state PCC is reported as a
precision diagnostic; exact restored replay and cache-consuming layer output are
required. Real-weight and recorded-input checks decide precision. Synthetic tests
serve as additional diagnostics and do not independently veto real-weight wins.
Batched/long fixtures reuse recorded activation segments and are labeled as such;
they do not claim to be an HF rollout of one native-length prefix.

## Scope and capability

This is a dense decoder with two attention kinds. Routed MoE, collectives, LM head,
sampling, generation, full-model assembly, and serving are absent from this stage.
The preserved contract is arbitrary valid logical lengths, paged64-token KV,
batches1–32, and native context262144 at batch1. Aggregate batch/context capacity
still depends on caller allocation. Opt-in million-token YaRN table setup is
inherited; million-token full-layer validation is not claimed.

The [context contract](../context_contract.json) records the validated capacity
and allocation policy. Final gate results are in
[final_gates_summary.json](final_gates_summary.json); local checkpoint SHAs are
recorded in the work log after independent review.

## Selected configuration

All attention and dense MLP projection weights use BFP4 and LoFi, packed from
the original host checkpoint during construction. BF16 residuals/activations,
FP32 recurrent state, and BFP8 paged KV are retained at their chosen boundaries.
Recurrent matrix reads use8x4, Kblock1, output subblock1x4, HiFi4 with FP32
destination accumulation. Their dtype/fidelity contract differs from projection
matmuls. Construction uploads separate DRAM-interleaved prefill and
DRAM-width-sharded decode weights.

| Decode role | Input cores | K block tiles | Readers per bank |
|---|---:|---:|---:|
| Linear QKV/A/B | 32 | 4 | 3 |
| Linear Z | 8 | 8 | 2 |
| Linear output | 8 | 8 | 2 |
| Full Q/K/V/gate | 32 | 2 | 3 |
| Full output | 8 | 8 | 2 |
| MLP gate and up, separately | 64 | 2 | 3 |
| MLP down | 48 | 8 | 2 |

Decode residual/norm uses32 width-sharded cores. Both output projections remain
sharded through the following residual operation at batch1. Larger logical
batches fold to one32-row tile for residual/norm and matmul, preserving public
`[B,1,4096]` tensors at required boundaries. Full head norms use8 width shards;
SDPA uses8x8 cores, Qchunk32/Kchunk256 and an explicit HiFi2 kernel config.
The query shard grid is reconciled with SDPA's actual reader grid. Grouped
prime-batch rotary tails go directly to DRAM to fit L1.

Prefill uses DRAM-interleaved activations and explicit 2D matmuls. Physical
sequence tensors of at least2048 use11x10/Kblock16; shorter tensors retain
8x8/Kblock8. Output blocks use divisors up to8x32 tiles, subblock height up
to2 for short prefill. Large prefill uses subblock bounds1x7, resolving to
1x6 for attention/output projections and1x7 for gate/up. This specializes
the program configuration without restricting logical sequence lengths. Native flat-Q/K GDN avoids
head-layout conversions; native KDA Conv1d+SiLU uses channel chunk1024.
Separate gate/up projections beat the packed prefill and decode candidates.
Linear QKV/A/B and full Q/K/V/gate packing beat tuned legal separate controls.
Persistent recurrent state uses L1 only within300KiB per bank; intermediates
require224KiB per bank. On this chip those correspond to batch<=16 and<=12.
Larger batches use DRAM, preserving batch32 support.

## Precision and resource repairs

The provisional BFP4 KV candidate passed the 2048-token pair, but broader
recorded-input tests exposed users 8 and 26 below PCC 0.995, both in batch 32
and as the identical batch-1 inputs. BFP8 KV passes all users. Exact cache
mapping, untouched-row checks, independent update controls and CPU SDPA over
the dequantized cache establish numerical sensitivity rather than a cache
addressing bug. Legal mixed K8/V4 storage also passes, but requires two cache
updates and loses traced decode: 0.432902 versus 0.427814 ms. Production keeps
BFP8 globally. See [cache AutoFix](AUTOFIX_cache4_batch.md) and
[precision results](cache_precision_summary.json).

Other repairs preserve exact restored trace output/state, input ownership,
and the public batch/context contract:

| Observed failure | Verified repair and evidence |
|---|---|
| Mixed BF16/FP32 sharded residual add replay mismatch | Homogeneous FP32 add with one BF16 rounding; [trace AutoFix](AUTOFIX_sharded_trace.md). |
| Batch L1 allocation overlap | Compact logical batch rows and measured recurrent-state/intermediate L1 budgets; [batch AutoFix](AUTOFIX_batch_l1.md). |
| Prime-batch rotary and SDPA shard mismatch | Free partial rotary temporaries, write tail directly to DRAM, map Q onto SDPA's actual first-B-core grid; batch resource regressions and work log. |
| Unaligned prefill retained many sharded decode outputs | Immediately collect the leading decode outputs in DRAM; existing TTNN recursive concat handles fan-in. Borrowed inputs remain untouched; [continuation AutoFix](AUTOFIX_final_continuation.md). |
| Incomplete reader profiler records | Capacity8000 and separate drain controls eliminate lost markers; complete alternating groups plus legal narrow-reader adaptations in [reader AutoFix](AUTOFIX_reader_profiler.md). |

Construction-only torch operations pack the original checkpoint and upload
weights. The measured prefill/decode path has no host conversion or fallback.
Native KDA convolution requires row-major input/history; these format boundaries
remain. Full SDPA and rotary require explicit legal shard layouts. The remaining
conversions reconcile those consuming-op contracts or public batch outputs;
the topology/movement plans measure the lower-movement alternatives.

## Profiler interpretation and advice

The advice-enabled tables and CSV live under
`tracy/{linear_attention,full_attention}/{baseline_recorded,optimized_release_v4}/`.
Each directory contains prefill and decode reports; the decode accounting JSON
links actual program attributes, dtypes, readers, physical bytes and timing.
Original op rows remain byte-identical compressed archives. Report text is
whitespace-normalized for repository hooks.

The initial dominant costs were DRAM BF16/HiFi4 projections, single-core
residual norms and FP32 recurrent reads. The precision-locked geometry search
and sharded residual path directly address those rows. Larger K blocks,
output blocking, smaller and larger grids, two/three DRAM readers and
independent attention/MLP LoFi trials are all measured. The final reader
comparison reaches approximately 446 GB/s for gate and 458 GB/s for down,
including BFP tile headers and reader padding, versus the report tool's
declared one-chip 512 GB/s peak model.

| Report advice or topology opportunity | Action and evidence |
|---|---|
| Reduce projection fidelity and weight traffic | Separate real-weight attention/MLP trials select BFP4/LoFi; final op rows verify the actual policy. |
| Put decode inputs in L1 and shard norm/residual | Shared gate/up input, sharded output retention, residual32 and down48 selected together; movement and batch controls cover legal boundaries. |
| Increase matmul K blocks/output subblocks | Per-role geometry inventories include all material legal divisors and output configurations; final packed and separate prefill MLP comparisons include adapted allocations. |
| Use more DRAM readers | Complete alternating reader1/2/3 comparisons, including legal N18 padding for narrow reader3; selected counts beat one-reader and legal alternatives. |
| Put prefill input in L1 | Legal adapted candidate passes but loses both kinds; native flat GDN and KDA convolution instead remove material prefill movement. |
| Replace repeated projection groups or primitives | Tuned packed QKV groups retained, packed MLP/all-GDN rejected by final compatible comparisons; native SDPA/conv/chunk composites selected. |
| Reduce FP32 recurrence cost | Explicit state-read geometry and bounded L1 placement win; outer broadcast and padded chunk decode pass but lose. Chunk composite internally fixes its precision despite accepting a supplied config. |
| Trace to remove dispatch gaps | Decode uses nonblocking trace windows with one synchronization; fixed-shape prefill capture passes exact state/output, refreshed real inputs and separate Watcher, saving140us/46us in the final control. Transfers, restoration and profiler drains stay outside timing. |

The generic report advice sometimes treats FP32 recurrent matmuls as if BFP8
fidelity rules applied, and may call a low-utilization row acceptable merely
because its output subblock exists. Source contracts and measured role-specific
candidates take precedence over those generic hints. Profiling uses four
decode replays to bound capture size; headline latency uses five warmed
32-replay windows without profiling. The same-run accounting reports profiler
overhead explicitly instead of mixing those two timing regimes.

## Large-prefill grid selection

Final separate-MLP topology changes the earlier grid conclusion:11x10/K16
passes real-weight PCC and improves prefill over8x8/K8. The complete grids,
K blocks and adapted L1 controls are in `final_prefill_grid*_plan.json` and
their per-run archives. K32 initially exceeds L1; M1 adaptation passes but
loses11.248151/9.507804ms. K64/M1 passes11.807900/10.186330ms. K128 initially
overlaps L1; minimalM1/N1 passes20.511717/17.383599ms. Those are measured
rejections, not API-error dismissals.

This changes only large-prefill matmul programs. The v2 batch matrix's
63-token prefixes pad to128, and its other batch prefixes remain below2048,
so their8x8/K8 programs and all decode programs are unchanged. Refreshed v4
short, native-context, Watcher and pair gates cover the promoted branch.

The generic decode report renders some DRAM matmuls as8 cores and even reports
over100% FLOPs, while its raw source marks CORE COUNT110. Those derived
core/FLOPs columns are a renderer limitation and are not hardware-utilization
evidence. Explicit runtime geometry/readers, raw kernel durations and
physical-byte bandwidth accounting support the conclusions instead.

## Prefill trace control

The existing runtime supports fixed-shape prefill capture without a separate
implementation. `test_optimized_prefill_trace.py` is the executable example;
it resets state outside timing, captures the real2048-token path, checks exact
output/state replay, then refreshes the captured input buffer with another
recorded prompt and checks HF again. Separate Watcher coverage passes.
[`prefill_trace_measurements.json`](prefill_trace_measurements.json) records:

The final trace control saves about140us linear and46us full attention.
The earlier v3 control measured14us/60us; host dispatch savings vary with

the same eager-prefill/traced-decode harness used for all candidate selection.
Native context remains validated through ordinary prefill; these additional
prefill-trace measurements cover2048 tokens rather than claiming native-size
trace allocation.
