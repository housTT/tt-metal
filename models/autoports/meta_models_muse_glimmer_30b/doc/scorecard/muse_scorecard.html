Reading the table: the KV cache holds 1,048,576 tokens, so 8 sequences of 130,816 tokens are resident at once and the 32-row decode graph serves every user count; concurrency is bounded by max_num_seqs 32, not by cache.

Random-token prompts of exactly the input length, output pinned with ignore_eos, greedy, streamed; users are concurrent requests held open as a closed loop, N is total requests in the row. TTFT is time to the first streamed token; TPOT = (E2EL − TTFT)/(output − 1); prefill tok/s = input/TTFT; decode tok/s = 1/TPOT; means over the row. One unrecorded warm-up per row, a distinct random seed per row, and prefix caching disabled for the sweep only — with it on, the seeded random prompts recur across warm-ups and rows and TTFT measures cache hits (a first pass showed a flat 1.9 s TTFT from 32,768 to 130,816 tokens and was discarded). 130,816 is the context boundary (131,072 − 256). Rows whose end-to-end latency exceeds 300 s end their input-length group. Measured 2026-09-24 on this build with both fixes applied, no other traffic on the server. Rows not measured: 65,536/32 users, 130,816/16 users, 130,816/32 users (predicted end-to-end > 300 s or beyond the measured envelope).
